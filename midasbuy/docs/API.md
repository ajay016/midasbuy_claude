# Midasbuy API

All endpoints are served by the FastAPI app mounted at **`/api`** (e.g.
`http://localhost:8000/api/...`). Interactive, always-up-to-date docs are
auto-generated by FastAPI:

- Swagger UI: `http://localhost:8000/api/docs`
- ReDoc: `http://localhost:8000/api/redoc`
- OpenAPI JSON: `http://localhost:8000/api/openapi.json`

There are two families of endpoints:

| Family | Style | Use it for |
|--------|-------|-----------|
| **Single** (`/player-info`, `/redeem`) | synchronous — runs in the request | one player / one code, interactive UI |
| **Bulk** (`/bulk/*`) | asynchronous — returns a job id to poll | many players / many codes |

Bulk endpoints never block: they create a **job**, hand it to a Celery worker,
and return immediately. You then poll the job for progress and per-row results.

---

## Single endpoints

### GET `/api/player-info`
Look up one player by UID.

Query params: `player_id` (required), `country_code` (default `bd`),
`account_id` (which logged-in Midasbuy account to use).

```bash
curl "http://localhost:8000/api/player-info?player_id=25849080551179560&country_code=bd&account_id=1"
```
```json
{ "success": true,
  "player": { "player_id": "25849080551179560", "username": "PlayerName", "zone_id": "" } }
```

### POST `/api/redeem`
Validate and/or redeem one code (the interactive flow used by the web UI).
See the schema in `/api/docs`.

## Bulk endpoints

Common idea: **POST to create a job → poll `GET /api/bulk/jobs/{id}`**.

`account_id` must be a **logged-in** `MidasbuyAccount` (it has the browser
session that performs the work). All items in one job use that one account.

### 1. POST `/api/bulk/player-info` — bulk player lookup
```json
{
  "account_id": 1,
  "country_code": "bd",
  "player_ids": ["25849080551179560", "51234567890123456"]
}
```

### 2. POST `/api/bulk/validate` — bulk code validation
For each row: looks the player up, then checks whether the code is valid.
**Does not redeem.**
```json
{
  "account_id": 1,
  "country_code": "bd",
  "items": [
    { "player_id": "25849080551179560", "pin_code": "ABCD-EFGH-IJKL" },
    { "player_id": "51234567890123456", "pin_code": "WXYZ-1234-5678" }
  ]
}
```

### 3. POST `/api/bulk/redeem` — bulk redeem
For each row the worker runs the **full flow**: player lookup → code validation
→ redeem (captcha is auto-solved if configured). Same request body as
`/bulk/validate`.
```json
{
  "account_id": 1,
  "country_code": "bd",
  "items": [
    { "player_id": "25849080551179560", "pin_code": "ABCD-EFGH-IJKL" }
  ]
}
```

#### Response (all three return the new job)
```json
{
  "job_id": 42,
  "job_type": "redeem",
  "status": "pending",
  "account_id": 1,
  "country_code": "bd",
  "total_items": 1,
  "processed_items": 0,
  "succeeded_items": 0,
  "failed_items": 0,
  "progress_percent": 0,
  "created_at": "2026-06-12T10:00:00Z"
}
```

### 4. GET `/api/bulk/jobs/{job_id}` — poll a job
Returns the job plus its items (`?include_items=false` to omit them).
`status` is one of `pending | running | completed | failed`.
```bash
curl "http://localhost:8000/api/bulk/jobs/42"
```
```json
{
  "job_id": 42, "job_type": "redeem", "status": "completed",
  "total_items": 2, "processed_items": 2, "succeeded_items": 1, "failed_items": 1,
  "progress_percent": 100,
  "items": [
    { "id": 101, "player_id": "25849080551179560", "pin_code": "ABCD-EFGH-IJKL",
      "status": "success", "success": true, "message": "Redeemed successfully.",
      "username": "PlayerName", "product_name": "60 UC" },
    { "id": 102, "player_id": "51234567890123456", "pin_code": "WXYZ-1234-5678",
      "status": "failed", "success": false, "message": "Redeem code is already used." }
  ]
}
```

### 5. GET `/api/bulk/jobs/{job_id}/items` — paginated items
Query params: `limit` (1–1000, default 100), `offset` (default 0). Handy for
large jobs.
```bash
curl "http://localhost:8000/api/bulk/jobs/42/items?limit=100&offset=0"
```

## Typical client loop (bulk redeem)
```python
import time, requests
BASE = "http://localhost:8000/api"

job = requests.post(f"{BASE}/bulk/redeem", json={
    "account_id": 1, "country_code": "bd",
    "items": [{"player_id": "2584...", "pin_code": "ABCD-EFGH-IJKL"}],
}).json()
jid = job["job_id"]

while True:
    j = requests.get(f"{BASE}/bulk/jobs/{jid}").json()
    print(j["status"], j["processed_items"], "/", j["total_items"])
    if j["status"] in ("completed", "failed"):
        break
    time.sleep(3)

for it in j["items"]:
    print(it["player_id"], it["success"], it["message"])
```

## Notes
- Items in one job run **sequentially** (they share one warm browser session).
  Different jobs for **different** accounts run in parallel across worker slots;
  two jobs for the **same** account are serialised by a Redis lock.
- A job never crashes on one bad row — that row is marked `failed` with a
  message and the job continues.
- Monitor jobs visually in Django admin under **Bulk → Bulk jobs**.
